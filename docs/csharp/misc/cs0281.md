# Compiler Error CS0281

Compiler Error CS0281 occurs when friend access is granted to an assembly, but the consuming assembly does not match the declaration in the <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute>.

Depending on the cause, the compiler reports one of the following error messages:

- *Friend access was granted to 'AssemblyName1', but the output assembly is named 'AssemblyName2'. Try adding a reference to 'AssemblyName1' or changing the output assembly name to match.*
- *Friend access was granted by 'AssemblyName1', but the public key of the output assembly ('Key') does not match that specified by the InternalsVisibleTo attribute in the granting assembly.*

## Remarks

Friend access enables an assembly to access non-public (`internal`) types and members in another assembly. For more information, see [Friend assemblies](../../standard/assembly/friend.md).

This error occurs in the following situations:

- **Assembly name mismatch**: The granting assembly's <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute> specifies a friend assembly name that does not match the output assembly name being compiled.
- **Public key mismatch**: When the granting assembly is strong-named, the grantee assembly must also be strong-named, and the <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute> must include the grantee assembly's full hexadecimal public key (not the 8-byte public key token). CS0281 occurs if the output assembly is unsigned or signed with a key whose public key doesn't match the value specified in the attribute.

## How to correct this error

To resolve this error, check the following:

- Verify that the output assembly name matches the assembly name specified in the <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute>.
- If the granting assembly is strong-named, ensure the output assembly is signed with the matching key file. In the project file (`.csproj`), enable signing:

  ```xml
  <PropertyGroup>
    <SignAssembly>true</SignAssembly>
    <AssemblyOriginatorKeyFile>path\to\key.snk</AssemblyOriginatorKeyFile>
  </PropertyGroup>
  ```

- Alternatively, update the `PublicKey` hexadecimal string in the granting assembly's <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute> to match the public key extracted from the signing key using `sn -tp key.snk`.
- If strong naming is not required, remove signing from both assemblies so that <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute> references only the simple assembly name.

## Example

The following sequence of code samples illustrates a strong-name public key mismatch that generates CS0281.

Strong-name keys can be generated using the [Strong Name Tool (Sn.exe)](../../framework/tools/sn-exe-strong-name-tool.md):

```cmd
sn -k CS0281.snk
sn -p CS0281.snk key.publickey
sn -tp key.publickey
```

The first assembly declares internal types:

```csharp
// CS0281.cs
// compile with: /target:library /keyfile:CS0281.snk
public class A {}
```

The second assembly grants friend access to `CS0281` with a specific public key:

```csharp
// CS0281_b.cs
// compile with: /target:library /keyfile:CS0281.snk /reference:CS0281.dll
[assembly: System.Runtime.CompilerServices.InternalsVisibleTo("CS0281, PublicKey=00240000048000009400000006020000002400005253413100040000010001004b2d4d56af7c50be2fcbbf97cb880b9e73ad84467a587191fef63aadc118a96cecf9d508cd679c907b6e20f71684300bdc2c0a851019af0c96b29bf8f1339753276041aefd67db46139e6348b3a12f29537b4dc6c2c19829df2c9ed6803f3c63c3b84cfa2728849386aea575c543a5f70fa85793d2946f15f7fe1ccb0c5e8fe0")]
class B : A {}
```

The third assembly attempts to access the friend assembly but has mismatched assembly identity attributes:

```csharp
// CS0281_c.cs
// compile with: /target:library /out:CS0281.dll /keyfile:CS0281.snk /reference:CS0281_b.dll
// CS0281 expected
[assembly: System.Reflection.AssemblyVersion("3")]
[assembly: System.Reflection.AssemblyCulture("en-us")]
class C : B {}
```
