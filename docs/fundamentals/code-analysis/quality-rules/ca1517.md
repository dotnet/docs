# CA1517: Use `ReadOnlySpan<T>` or `ReadOnlyMemory<T>` instead of `Span<T>` or `Memory<T>`

| Property                            | Value |
|-------------------------------------|-------|
| **Rule ID**                         | CA1517 |
| **Title**                           | Use `ReadOnlySpan<T>` or `ReadOnlyMemory<T>` instead of `Span<T>` or `Memory<T>` |
| **Category**                        | [Maintainability](maintainability-warnings.md) |
| **Fix is breaking or non-breaking** | Non-breaking |
| **Enabled by default in .NET 10**     | No |
| **Enabled by default in .NET 11**   | As suggestion |
| **Default severity in .NET 11**    | Info (IDE suggestion) |
| **Applicable languages**            | C# and Visual Basic |

## Cause

A method uses a `Span<T>` or `Memory<T>` parameter only in ways that don't require write access.

## Rule description

Use <xref:System.ReadOnlySpan`1> or <xref:System.ReadOnlyMemory`1> for data that a method doesn't modify. The read-only type makes the method's intent clear and lets callers pass data that they can't modify.

By default, the analyzer checks private and internal methods. It doesn't report virtual methods, overrides, or interface implementations.

## How to fix violations

Change the parameter type to its read-only counterpart. In C#, apply the code fix. The analyzer also reports violations in Visual Basic, but it doesn't provide a Visual Basic code fix.

## Examples

The following code shows violations of CA1517 because the methods only read their parameters:

```csharp
static int GetFirst(Span<int> values) => values[0];

static int GetLength(Memory<byte> data) => data.Length;
```

Change the parameter types to their read-only counterparts:

```csharp
static int GetFirst(ReadOnlySpan<int> values) => values[0];

static int GetLength(ReadOnlyMemory<byte> data) => data.Length;
```

## When to suppress warnings

Suppress the warning only when the method's contract requires a writable parameter or when the method uses the data in a way that requires write access.

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable CA1517
// The code that's violating the rule is on this line.
#pragma warning restore CA1517
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](../configuration-files.md).

```ini
[*.{cs,vb}]
dotnet_diagnostic.CA1517.severity = none
```

For more information, see [How to suppress code analysis warnings](../suppress-warnings.md).
