# CA1876: Do not use 'AsParallel' in 'foreach'

| Property                            | Value |
|-------------------------------------|-------|
| **Rule ID**                         | CA1876 |
| **Title**                           | Do not use `AsParallel` in `foreach` |
| **Category**                        | [Performance](performance-warnings.md) |
| **Fix is breaking or non-breaking** | Non-breaking |
| **Enabled by default in .NET 10**     | No      |
| **Enabled by default in .NET 11**   | As suggestion |
| **Applicable languages**            | C# and Visual Basic |

## Cause

A `foreach` loop enumerates the result of calling `AsParallel()` directly.

## Rule description

The `foreach` statement processes each item serially. Calling <xref:System.Linq.ParallelEnumerable.AsParallel*> on the collection doesn't make the loop run in parallel.

## How to fix violations

Remove `AsParallel()` if the loop should run serially. To process each item in parallel, use <xref:System.Threading.Tasks.Parallel.ForEach*>. To parallelize LINQ query operations, call `AsParallel()` before those operations, then enumerate the query or call `ForAll`.

## Examples

The following code shows a violation of CA1876:

```csharp
var values = new[] { 1, 2, 3 };
foreach (var value in values.AsParallel())
    Console.WriteLine(value);
```

To process each item in parallel, use `Parallel.ForEach`. Use this approach only when the work can run concurrently; it doesn't preserve item order.

```csharp
var values = new[] { 1, 2, 3 };
Parallel.ForEach(values, value => Console.WriteLine(value));
```

The following Visual Basic code shows a violation:

```vb
Dim values = {1, 2, 3}
For Each value In values.AsParallel()
    Console.WriteLine(value)
Next
```

To process each item in parallel, use `Parallel.ForEach`:

```vb
Dim values = {1, 2, 3}
Parallel.ForEach(values, Sub(value) Console.WriteLine(value))
```

## When to suppress warnings

Suppress the warning only when you use `AsParallel()` for another reason. The `foreach` loop itself still runs serially.

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable CA1876
// The code that's violating the rule is on this line.
#pragma warning restore CA1876
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](../configuration-files.md).

```ini
[*.{cs,vb}]
dotnet_diagnostic.CA1876.severity = none
```

For more information, see [How to suppress code analysis warnings](../suppress-warnings.md).
