# CA1878: Prefer ReadOnlySpan properties over readonly array fields

| Property                            | Value                                                     |
|-------------------------------------|-----------------------------------------------------------|
| **Rule ID**                         | CA1878                                                    |
| **Title**                           | Prefer ReadOnlySpan properties over readonly array fields |
| **Category**                        | [Performance](performance-warnings.md)                    |
| **Fix is breaking or non-breaking** | Non-breaking                                              |
| **Enabled by default in .NET 11**   | As suggestion                                             |
| **Applicable languages**            | C#                                                        |

## Cause

A private static readonly one-dimensional array field contains supported constant values, and all observed usages can be safely rewritten to use a <xref:System.ReadOnlySpan`1> property.

## Rule description

A static readonly array field requires a managed array allocation. When a <xref:System.ReadOnlySpan`1> property returns supported constant data, the C# compiler can lower the data without allocating a managed array. Replacing the field with a property can reduce allocations while preserving read-only access to the data.

The analyzer supports the following element types:

- `bool`, `byte`, and `sbyte` are supported whenever <xref:System.ReadOnlySpan`1> is available.
- `short`, `ushort`, `char`, `int`, `uint`, `float`, `long`, `ulong`, and `double` are supported only when the target compilation exposes the public static <xref:System.Runtime.CompilerServices.RuntimeHelpers.CreateSpan``1(System.RuntimeFieldHandle)?displayProperty=nameWithType> method. .NET 7 and later reference assemblies expose this method.

The analyzer doesn't diagnose arrays of `decimal`, `nint`, `nuint`, enum types, arbitrary structs, or reference types. It also doesn't diagnose jagged arrays or multidimensional arrays.

## How to fix violations

Replace the array field with an expression-bodied property that returns <xref:System.ReadOnlySpan`1>.

The code fix rewrites eligible usages of the field. For supported `AsSpan` calls, it removes a redundant call or replaces the call with an equivalent span operation, such as `Slice`. The code fix isn't offered when it can't preserve the semantics of every usage.

## When to suppress warnings

Suppress a warning if you intentionally retain the array's identity or mutability, or if preserving API compatibility requires the member to remain an array field. The rule only reports private static readonly fields whose observed usages can be safely rewritten.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable CA1878
// The code that's violating the rule is on this line.
#pragma warning restore CA1878
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](../configuration-files.md).

```ini
[*.{cs,vb}]
dotnet_diagnostic.CA1878.severity = none
```

For more information, see [How to suppress code analysis warnings](../suppress-warnings.md).
